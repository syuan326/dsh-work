# DSH 工作 / 个人会话模式

为 DeepSeek Harness（DSH）的 Web 界面增加 **工作模式**和**个人模式**。在新会话发出第一条消息前选择模式，随后 Agent 使用对应的工作区工具。工作模式不会获得个人账本工具；个人模式不会获得工作区的邮件、笔记、日历、任务或计划工具。

| 项目 | 当前仓库 |
| --- | --- |
| 组合包 | `@local/dsh-workspace-agent-modes` |
| 插件版本 | `1.0.0` |
| DSH 版本 | 清单精确声明 `0.2.2-rc.3`，不是 `0.2.x` 通用兼容承诺 |
| 界面 | DSH Web；选择器提供简体中文和英文文案 |
| 配套组合包 | `@local/dsh-personal-workspace`，不在本仓库内，须另行取得 |

**本插件负责选择预设和限制工具，不提供邮件、笔记、日程或账本的数据服务。** 相关服务、存储与账户配置由配套组合包负责。克隆本仓库不会获得这些数据，也不会自动连接任何邮箱。

## 两种模式有什么区别

| 能力 | 工作模式 `work-mode` | 个人模式 `personal-mode` |
| --- | --- | --- |
| 邮件 | `work_mail_*` | `personal_mail_*` |
| 笔记 | `notes_work` | `notes_personal` |
| 日历与任务 | `planner_work` | `planner_personal` |
| 周期计划与打卡 | `plans_work` | `plans_personal` |
| 个人账本 | 不开放 | `ledger_options`、`ledger_query`、`ledger_summary`、`ledger_planning`、`create_ledger_entry` |

表格描述的是**模式允许哪些工具名**，不是安装后一定会出现的工具清单。工具仍需由配套插件注册，邮件还取决于该插件的账户配置和权限。`planner_*` 用于日历与任务，`plans_*` 用于周期计划和打卡；两者不是同一套记录。

两种预设都保留了常见的 DSH 通用能力，例如文件读取与搜索、Shell、技能、目标、子代理、工作流、网页访问和 Office 工具。实际可用能力仍受运行环境、Profile 与工具权限约束。切换会话预设不等同于更换模型、账户、文件目录或左侧导航分类。

## 安装与启用

### 1. 检查前提

- 使用 DSH `0.2.2-rc.3` 的 Web Profile。其他版本、Desktop 原生界面和非 Web 启动方式未在此文档中承诺兼容。
- 能访问此 GitHub 私有仓库，并能从自己的可信来源取得兼容的 `@local/dsh-personal-workspace`。本仓库不提供配套包下载，也不包含邮箱、密钥或 Profile 的私有配置。
- 在同一个目标 Profile 中使用两个包。建议先在测试 Profile 验证，尤其是已配置邮箱或使用自定义 Profile patch 时。

### 2. 安装配套组合包，再安装本组合包

先通过 DSH 的插件管理器，将你已有的 `@local/dsh-personal-workspace` 安装并启用到目标 Profile；确认其配置及工具可用。然后克隆本仓库：

```bash
git clone https://github.com/syuan326/dsh-work.git
```

若使用当前版本的 DSH CLI，可在克隆目录的**上一级**执行：

```bash
# web 是示例 Profile 名称，部署时请替换为实际运行的 Web Profile。
dsh plugin --profile web add ./dsh-work
```

这是本地目录安装，DSH 会链接 checkout；安装后不要删除或随意移动该目录。只运行 `git clone`、在源码目录执行 `npm install`，或把文件复制到任意目录，都不会自动将 bundle 加到当前 Profile。此项目的运行入口是已提交的 JavaScript，不需要单独构建前端，也未声明安装脚本。

### 3. 检查配置层与启动结果

```bash
dsh --profile web --dump-config
```

检查输出中是否能找到组合包层及 `workspace-modes-ui`、`preset-work-mode`、`preset-personal-mode`。如果分享输出排障，先删除凭据、账户地址和其他私有配置。

然后按原来的方式打开该 Profile 的 DSH Web 页面；如果实例没有加载最新的包或配置，重启对应 DSH 实例，再刷新浏览器。创建一个空白会话，检查输入区是否出现“会话模式”以及“工作”“个人”两张卡片。

> **已有邮箱配置时请先核对有效配置。** 本组合包以 `personal-workspace` 为行 ID 覆盖配套组合包的配置；这个 DSH 版本的行覆盖会替换整段 `config`，不是按键深度合并。后加载的 Profile 本地 patch 也可能覆盖本组合包的值。请在较高优先级的本地层中保留完整所需配置，并保留 `workMail.presets: [work-mode]`、`personalMail.presets: [personal-mode]`，除非你有意改变路由。不要将本地配置或凭据提交到仓库。

## 日常使用

1. 在 DSH Web 主会话视图中创建一个空白会话。
2. 在输入区点击 **工作**或**个人**。切换完成后，当前选项会显示选中标记；提示失败时，确认仍是空白会话后再试。
3. 确认已选中的模式，再发送第一条消息。插件不依据消息内容推断模式，也不自动选中某一张卡片。
4. 已开始的会话不再显示本插件的选择器。要处理另一空间的事务，另开一个空白会话并选择对应模式。

例如，工作会话中可以查询工作待办、查看工作日历、记录项目笔记；个人会话中可以查询个人计划或账本。实际发送邮件、写入账目或修改记录时，仍须遵循底层工具的授权与确认规则。切换模式本身不会读写这些业务记录，也不会把一个空间的数据迁移到另一个空间。

## 模式如何生效

1. **加载组合包。** [组合配置](cordis.patch.yml) 注册 Web UI 入口和两个 Agent 预设。每个预设都挂载 `workspace-mode-tool-mask`，并传入 `space: work` 或 `space: personal`。补丁还覆盖 `personal-workspace` 行，将配套插件时区设为 `Asia/Shanghai`，并分别配置工作、个人邮件的预设列表。
2. **显示卡片。** [Web 客户端](client.js) 在 `conversation.input.dock` 注册选择器。仅当会话是空白、处于主视图且能查到两个没有被标记为异常的预设时才显示。如果预设列表查不到，选择器不渲染，并不替换 DSH 自带的预设选择器。
3. **切换预设。** 客户端调用 `remote.agentPresets.select`，而不只是改变按钮样式。切换期间会尝试暂时阻止提交，且不会覆盖或清除其他插件设置的阻止状态。选中态读取会话实际的 `agentPreset` 投影。
4. **限制工具。** [模式掩码](index.js) 在对应 Agent 作用域调用 `ctx.tools.restrict({ deny })`。它在激活时扫描已注册的工具，并监听 `tools/change` 以处理后注册的工具。同名工具卸载后重新注册不会解除已添加的限制。另一空间的笔记、日历/任务、计划及邮件按表中的名称匹配；工作模式另有五个账本工具的拒绝名单。

默认时区和邮件预设列表由组合配置传给配套插件；此处没有单独设置面板，也没有改动 DSH 全局时区。

## 隔离边界

- **隔离的是这两个预设下匹配的 Agent 工具。** 拒绝工具不仅不会进入对应作用域的模型工具清单，也不能经该作用域的工具执行查找取得。工具仍可在宿主注册，不能把这理解为全局卸载。
- **这是拒绝名单，不是完整的权限白名单。** 未匹配的通用工具或由其他插件以不同名称暴露的工具不会自动被拦截。新增账本工具时，需评估是否补充名单；另一个预设或入口也不自动继承这里的规则。
- **不是账户、进程或文件系统隔离。** 插件不改变 Shell、文件访问、网络访问或宿主服务权限。配套数据的存储隔离、邮箱的认证和其他访问入口需要由各自组件或部署环境保证。不能用模式选择代替独立账户、独立实例或操作系统权限边界。

在已经装好配套组合包的 **DSH Shell** 中，从仓库根目录运行：

```bash
node --test isolation.test.mjs
```

测试通过 `DSH_INSTALL_DIR` 加载运行时模块，并通过 `DSH_PROFILE_DIR` 查找 `@local/dsh-personal-workspace` 的邮件工具门控模块。单独克隆本仓库后，在没有这些路径和依赖的普通 Shell 中运行，不能完成这项集成测试。测试在内存注册样例工具，不连接实际邮箱、不写入账本；它检查两种作用域的工具清单、执行查找和宿主注册状态，不覆盖浏览器渲染或邮箱连通性。

改动预设或 Web 客户端时，建议额外手动验证：空白主会话显示卡片、能切换并正确显示选中状态、发送首条消息后卡片隐藏、已打开的非空会话和非主视图不出现卡片、工作模式没有个人账本工具，并确认配套插件的邮件权限仍符合预期。

## 故障排查

| 现象 | 优先检查 |
| --- | --- |
| 无法克隆或返回 404 | 仓库为私有，请确认当前 GitHub 账号有访问权限，且 Git 使用了正确的认证方式。 |
| 安装提示 DSH 版本不匹配 | 清单要求 `0.2.2-rc.3`；先核对当前运行版本，不建议未经验证就放宽约束。 |
| 看不到“会话模式”卡片 | 新建空白会话并从主视图打开；核对启用的是当前 Web Profile、两个预设都正常，必要时重启实例并刷新页面。 |
| 点击后提示切换失败 | 确认没有先发送消息，当前输入不忙，且能正常访问 DSH 实例。也可用 DSH 自带的预设选择器核对两个 ID。 |
| 有卡片，但缺少笔记、日历、任务或计划 | 检查 `@local/dsh-personal-workspace` 是否在同一个 Profile 启用、服务是否成功启动，以及对应工具是否已注册。 |
| 邮件工具不出现或账户配置失效 | 核对邮箱配置、预设列表和 `personal-workspace` 的最终生效配置；尤其注意高优先级 patch 是否整体替换了 `config`。 |
| 工作模式看不到个人账本 | 这是预期行为。应在新空白会话中选择个人模式，再确认配套插件的账本工具可用。 |
| 测试报模块或路径不存在 | 在目标 DSH Shell 中确认 `DSH_INSTALL_DIR`、`DSH_PROFILE_DIR` 可用，并确认同一 Profile 已安装兼容的配套组合包。 |

## 更新与停用

- **更新：** 如果使用本地 checkout 安装，在同一目录更新到目标提交；先检查 DSH 版本约束及配置差异，再重启对应实例、刷新 Web 页面，并用空白会话复验。不要依赖热更新替换所有已加载模块。
- **停用：** 可在目标 Profile 的插件管理器中禁用本组合包。若要通过 CLI 移除：`dsh plugin --profile web remove @local/dsh-workspace-agent-modes`。这里的 `web` 同样应替换为实际名称；不要误移除配套组合包。
- **停用后：** 检查配套插件的有效邮箱配置是否仍引用 `work-mode` / `personal-mode`。已保存的会话可能仍引用已移除的预设，必要时用可用预设新建会话。停用本包不等同于删除配套数据，也不是备份或迁移操作。
