# 个人与工作笔记

DSH 0.2.2-rc.3 原生插件，从 `nonenot_plugin_agent` 的笔记模块提取核心能力，不依赖原 Python/Vue 服务。

## 使用

刷新现有 DSH 页面，在左侧选择 **个人笔记** 或 **工作笔记**。新建笔记，填写标题、Markdown 正文和逗号分隔的标签，点击保存。编辑页可切换安全预览；支持置顶、归档、全文搜索和精确标签筛选。

若已安装“左侧导航分类”插件，它会把未知的新入口默认放在“工作”。可在左侧分类设置中把“个人笔记”归入“个人”；这只影响入口位置，不影响数据隔离。

阅读页可查看完整历史版本，并把任意历史内容恢复为新版本。删除需二次确认，会删除当前记录及可浏览的历史，不能撤销；内部幂等收据可能保留先前写入结果和正文，因此不等同于安全擦除。恢复也需确认，且不会抹去既有历史。多个客户端同时编辑时，过期版本不能覆盖新数据，草稿保留供人工合并。

草稿及待确认写入仅在当前浏览器标签页的 sessionStorage 中临时保存（个人/工作分开）。浏览器禁用存储时会给出提示；已保存的数据由 Host 持久化，不依赖浏览器。网络结果不确定时，用“重试同一请求”复用原 request_id，避免重复创建。

## 数据与工具

- Host storageDomain：`split_notes_personal`、`split_notes_work`，分别持久化当前笔记、完整历史和幂等收据。
- Agent 工具：`notes_personal`、`notes_work`。支持 list/get/versions/save/delete/restore，与页面共享同一个 Host 操作实现。写操作必须有用户明确意图，先读最新 id/version，生成稳定 UUID 作为 request_id；原参数重试必须复用同键。
- 标题最多 200 字符；正文最多 100000 UTF-16 单元；最多 20 个标签，各最多 40 字符。
- 每个空间最多 500 篇笔记、10000 个完整历史快照、2000 条持久化幂等收据，总计最多 32 MiB（含历史及收据）。达到上限会明确拒绝新写入，不静默淘汰历史或收据。
- 个人与工作为应用层分区，不是不同账号之间的权限系统；具有两套工具权限的 Agent 可在用户授权下访问两个空间。

## 与原项目的边界

保留笔记标题/正文/标签、检索和版本历史能力，新增置顶和归档。不会自动导入原数据库，不关联原工作项目、来源会话或文件，不生成长期记忆，不向旧服务发送请求。Markdown 为安全子集（标题、列表、粗体、代码）；HTML、外链图片及脚本不执行。图标为本插件原创 SVG。

## 检查

```sh
npm test
node --check client.js
```

测试覆盖隔离、CRUD、完整快照、恢复、版本冲突、跨重启幂等、容量限制、工具与页面共享操作、鉴权和请求长度限制。无浏览器控制时，实际渲染、浅深色及点击流程须在当前 DSH 页面人工确认，不将语法检查等同于视觉验证。
